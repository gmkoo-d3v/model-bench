# 桜の庭 — Voxel Pagoda Garden 벤치마크

요즘 LLM 벤치마크로 유행하는 "단일 HTML 복셀 정원" 과제를 여러 모델에 똑같이 시키고, 결과물을 브라우저에서 직접 띄워 검증한 기록입니다.

과제의 원형은 하늘에 떠 있는 복셀 섬 위에 5층 목탑·토리이·벚나무·잉어 연못을 올리고, 꽃잎이 흩날리며 낮/밤이 순환하는 Three.js 데모입니다. 원본 영상에서 프레임을 뽑아 요구사항을 [`SPEC.md`](SPEC.md)로 정리했고, 모든 모델에 [`prompt.txt`](prompt.txt)와 함께 그대로 전달했습니다.

## 등급 기준

- **A** — 사양 전 항목 동작, 눈에 띄는 결함 없음
- **B** — 전 항목 동작, 사소한 결함 1–2개 (프레이밍·규모)
- **C** — 동작하지만 사용자가 바로 마주치는 결함 있음
- **F** — 첫 화면부터 결과물이 보이지 않음

등급은 **모델이 내놓은 그대로**를 기준으로 매겼습니다. 사용자가 받는 건 그 파일이기 때문입니다.

## 검은 화면을 고쳐주면 순위가 바뀌는가

Astra와 Luna는 `vertexColors` 한 단어만 바꾸면 정상으로 돌아옵니다. 그 패치본까지 같은 줄에 세우면 상위권은 이렇게 갈립니다.

| 기준 | 앞서는 쪽 |
|---|---|
| UI 패널 완성도 | **Astra(패치)** ≥ Sol > Sonnet ≈ Opus |
| 장면 풍성함 | **Sonnet** > Sol ≈ Astra(패치) > Opus |
| 탑 조형 | Astra(패치) ≈ Sol ≈ DeepSeek |
| 연못 | **Sol** > Sonnet > Astra(패치) ≈ Opus |
| 카메라 프리셋 | **Sol ≈ Opus** > Sonnet(빽빽함) > Astra(패치, 5번 처마에 걸림) |
| 엔지니어링 견고성 | **Opus ≈ Sonnet** (`performance.now()` 이징) > 나머지 |
| 비용 | Terra·Luna(≈ 8–9분) … Sonnet(74분, 42만 토큰) |

패치 기준으로 보면 **Astra는 1위 후보 셋(Astra·Sol·Sonnet) 중 하나**입니다. UI를 가장 중시하면 Astra, 결함 없는 균형이면 Sol, 장면의 풍성함이면 Sonnet입니다. 어느 하나가 모든 축에서 앞서지는 않습니다.

다만 패치본의 점수는 모델 혼자 낸 점수가 아닙니다. 결함을 찾고 고친 건 검증자였고, 모델은 검은 화면을 "완료"로 보고했습니다.

## 실험 조건

| 경로 | 모델 | 실행 방식 |
|---|---|---|
| OpenCode | qwen3.8-flash-next-nvfp4 (로컬 GX10, vLLM) | `ds-worker worker` |
| codex CLI 0.166.0 | gpt-6-astra, gpt-6-luna, gpt-6.1-sol, gpt-6.1-terra | `codex exec -m <model> -c model_reasoning_effort="max" -s workspace-write` |
| Claude Code 서브에이전트 | claude-opus-5.5, claude-sonnet-5.5 | Agent 도구, effort `max` |
| 사용자 별도 실행 | deepseek-v4.1-flash (max reasoning) | 경로·프롬프트 미확인 |
| 감독자 직접 작성 | claude-opus-5 | 정답지 |

**같은 사양서, 같은 프롬프트, 같은 검증 기준**을 썼습니다. 다만 실행 하네스가 셋으로 갈리므로 "모델 단독 실력"이라기보다 "모델 + 그 모델이 돌던 에이전트 환경"의 결과로 읽어야 합니다. 특히 브라우저로 자기 결과물을 볼 수 있었는지가 결과를 크게 갈랐습니다(아래 참고).

`gpt-6.1-luna`는 카탈로그에 없어서 `gpt-6-luna`로 대체했습니다. 한 세대 아래 모델입니다.

## 검증 방법

모델이 스스로 보고한 VERIFICATION은 참고만 하고, 아래를 전부 직접 다시 했습니다.

1. `SPEC.md`의 `node -e` 검증 커맨드 재실행
2. 로컬 HTTP 서버로 띄워서 콘솔 에러 확인 (`file://`로는 ES 모듈이 안 돌아갑니다)
3. 첫 화면 스크린샷, 상태줄의 복셀 수·fps 확인
4. 카메라 프리셋 1–5를 키보드로 눌러 각각 스크린샷
5. Time 슬라이더를 21:30으로 밀어 밤 장면·반딧불이 확인
6. Regenerate seed, Wireframe 토글

## 모델별 분석

### gpt-6.1-sol · max — A

사양 범위 안에서 가장 균형이 좋습니다. 축 하나에서 1등은 아닐 수 있어도 약점이 없습니다.

- **첫 화면 프레이밍이 처음부터 맞습니다.** Luna·Terra·qwen이 섬을 잘라먹었고 정답지도 처음엔 그랬는데, Sol은 첫 로드부터 섬 전체가 여유 있게 들어옵니다.
- 연못이 제대로 된 규모입니다. 물빛에 깊이 그라데이션이 있고 나무다리가 가로지릅니다.
- 탑 상륜부를 금색 링 여러 단으로 쌓아 가장 정교합니다.
- UI 카피("LIVING GARDEN", "FIND A LITTLE PERSPECTIVE"), 시드 표시, `Shift + drag to pan` 안내까지 넣었습니다.
- 브라우저 확인을 시도했지만 차단당했고, 로그에 `[blocked]`로 정직하게 남겼습니다. 눈으로 못 보고도 올바른 코드를 쓴 경우입니다.
- 약점: 카메라 이징이 프레임 누적 방식이라 창이 백그라운드로 가면 프리셋 이동이 길게 늘어집니다.

### claude-opus-5.5 · max — A

가장 짧은 코드로 가장 견고한 결과를 냈습니다.

- **1,198줄로 정답지 다음으로 짧은데** 사양 전 항목이 동작합니다.
- **카메라 이징을 `performance.now()` 기준으로 짠 둘 중 하나입니다**(나머지 하나는 Sonnet). 다른 모델은 전부 `dt` 누적이라 저프레임 환경에서 카메라가 제때 도착하지 않습니다. 정답지도 처음엔 `dt` 누적으로 짰다가 검증 중에 고쳤습니다.
- `vertexColors: true`를 반딧불이 Points에만, 그것도 color 속성을 직접 만든 뒤에 썼습니다. InstancedMesh에는 쓰지 않았습니다. Astra·Luna가 넘어진 자리를 정확히 비켜갔습니다.
- **스스로 브라우저로 확인하고 고쳤습니다.** 처음엔 연못·토리이·벚꽃 프리셋이 구조물 안에 박혀서 다시 잡았고, 다리 난간도 얇게 바꿨다고 보고했습니다. 정답지를 만들 때 밟은 것과 같은 두 가지입니다.
- 약점: 연못이 작고 벚나무가 성겨서 섬이 다소 휑합니다.
- 부분 확인: 에이전트가 144fps를 봤다고 보고했습니다. Opus 파일에서는 쓰로틀 때문에 29–76fps로만 찍혀 직접 확인하지 못했지만, 같은 검증 환경에서 쓰로틀이 풀린 순간 Sonnet 파일이 144fps를 찍었으므로 화면 주사율 상한으로서 그럴 만한 숫자입니다.

### gpt-6.1-terra · max — B

codex로 돌린 GPT 네 개 중 가장 빨리 끝났고(≈ 9분, 토큰 76,728로 최소), 결함 없이 동작합니다.

- `vertexColors` 함정을 피했습니다. 소스 전체에 0건입니다.
- 프리셋 3·5 모두 구조물 밖에서 대상을 제대로 잡습니다.
- 브라우저 확인이 차단되자 로그에 "실제 렌더링과 60fps는 `[uncertain]`"이라고 적었습니다. 확인 못 한 것을 확인했다고 하지 않았습니다.
- 감점: 첫 화면 카메라가 가까워서 섬 아래쪽과 왼쪽이 잘립니다.

### deepseek-v4.1-flash · max — B

디테일 조형이 강하고 약점이 분명합니다.

- **탑이 정답지보다 낫습니다.** 금색 마스트·링·보주로 상륜부를 쌓았고, 1층에 어두운 문 안쪽 공간을 파서 입구로 보이게 했습니다.
- 하늘 그라데이션 10스톱, ACES 톤매핑, 잉어를 9복셀 몸통에 쿼터니언으로 진행 방향을 물렸습니다.
- 사양에 없던 석등 2기, 바닥에 떨어진 꽃잎, 조작 힌트 토스트를 얹었습니다.
- 감점: **연못이 물 복셀 51개뿐이라 웅덩이 수준**이고 잉어가 거의 안 보입니다.
- 감점: 프리셋 이동 중 `controls.enabled = false`로 잠그는데 이징이 `dt` 누적이라, 저프레임에서 1.2초짜리 연출이 십수 초로 늘어나는 동안 사용자가 궤도 조작을 못 합니다.
- 상태줄 "voxels" 수에 꽃잎 900장이 섞여 있습니다.

### qwen3.8-flash-next-nvfp4 · local — C

로컬 모델로 1,499줄짜리 단일 파일을 끝까지 완주했다는 점 자체가 성과입니다.

- `ds-worker` 결과 `CLEAN_RESULT`, 39분, 툴 호출 148회.
- 색·낮밤·반딧불이·Regenerate·Wireframe 모두 동작, 60fps.
- **카메라 프리셋 5개 중 3개가 구조물 안에 박힙니다.** 3 Pond는 탑 구조물 속, 4 Torii는 토리이 기둥 사이, 5 Blossoms는 벚꽃 캔버스 내부라 화면이 분홍색으로 꽉 찹니다. 60fps 상태에서 재현했으므로 쓰로틀 착시가 아닙니다.
- 상태줄이 패널 하단이 아니라 화면 좌하단 구석에 따로 떨어져 있습니다.

### gpt-6-astra · max — F (패치 시 B+)

UI 완성도는 여덟 개 중 최고인데, 한 단어 때문에 화면이 새까맣습니다.

- **모든 복셀이 검게 렌더링됩니다.** 지오메트리는 16,541개 전부 있고 60fps로 돌지만 색이 하나도 안 나옵니다.
- 원인: InstancedMesh 머티리얼에 `vertexColors: true`를 켰습니다 (6곳). `setColorAt()`으로 준 인스턴스 색은 three.js가 `instanceColor`로 알아서 쓰는데, `vertexColors`까지 켜면 셰이더가 지오메트리의 `color` 속성을 곱하려 듭니다. `BoxGeometry`에는 그런 속성이 없어서 0으로 들어가고 전부 검게 곱해집니다.
- **이 한 단어를 `false`로만 바꾸면 정상 렌더링됩니다.** [`gpt-6-astra-max-patched.html`](gpt-6-astra-max-patched.html)이 그 결과입니다. 그 외에는 한 글자도 안 바꿨습니다.
- 패치 후 보면 탑이 날렵하고 처마가 층마다 제대로 벌어집니다. "FIND YOUR VIEW" 섹션 라벨, 벚꽃 아이콘, 시드 표시까지 넣었습니다. 5 Blossoms 프리셋은 처마 안쪽에 반쯤 걸립니다.
- 마지막에 스스로 브라우저로 렌더링을 확인하려다 **`usage limit`에 막혔습니다.** 파일 작성과 정적 검증은 그 전에 끝난 상태였습니다. 그 확인이 성공했다면 검은 화면을 보고 고쳤을 가능성이 높습니다.

### gpt-6-luna · max — F (패치 시 B)

Astra와 같은 자리에서 넘어졌는데, 넘어진 방식이 더 흥미롭습니다.

- 모든 복셀이 검게 렌더링됩니다. 원인도 같습니다 — `createVoxelMaterial()`의 `vertexColors: true`.
- **그런데 Luna는 `vertexColors`를 올바르게 쓸 줄 압니다.** 같은 파일의 반딧불이 Points에서는 바로 앞줄에 `setAttribute("color", ...)`로 실제 color 속성을 만든 뒤에 씁니다. 개념을 모르는 게 아니라 InstancedMesh의 `instanceColor`와 혼동한 것입니다.
- 복셀 머티리얼 한 줄만 고친 [`gpt-6-luna-max-patched.html`](gpt-6-luna-max-patched.html)은 정상 렌더링됩니다. 반딧불이 줄은 그대로 뒀습니다.
- 패치 후: 탑의 붉은 띠가 선명하고 벚나무 캐노피가 풍성합니다. 첫 화면 카메라가 가까워 섬이 잘립니다.
- 로그에 "브라우저에서 WebGL 장면을 직접 실행해 확인하지는 않았습니다"라고 스스로 적었습니다.
- 토큰 140,629로 GPT 네 개 중 가장 많이 썼습니다.

### claude-sonnet-5.5 · max — A

사양을 가장 크게 넘어선 결과물이고, 가장 비싸게 만든 결과물입니다.

- **장면이 가장 풍성합니다.** 사양에 없던 복셀 구름, 신사, 정자, 등나무 퍼걸러, 덤불, 석등을 직접 추가했습니다. 섬 주위로 구름이 떠다닙니다.
- `vertexColors: true`는 반딧불이 Points에만, color 속성을 만든 뒤에 썼습니다. 함정을 피했습니다.
- **카메라 이징이 `performance.now()` 기준입니다.** Opus와 함께 둘뿐입니다.
- 시드를 URL 해시(`#seed=…`)에 넣어 같은 섬을 링크로 공유할 수 있습니다.
- 스스로 브라우저로 확인했고, Node에서 시드 400개로 월드 생성을 돌려 오류 없음·나무 5그루·잉어 2–3마리·복셀 14.9k–17.1k를 확인했다고 보고했습니다. 멀리 있는 구름이 그리드를 넘어 섬 안으로 감겨 들어오는 버그를 찾아 그리드를 256×256으로 키웠다고도 했습니다.
- 검증 환경에서 쓰로틀이 풀린 순간 **144fps**를 찍었습니다. 여덟 개 중 직접 확인한 최고치입니다.
- 감점 아님, 참고: Auto-rotate가 기본으로 켜져 있습니다. 사양에 기본값이 없어 결함은 아니지만, 프리셋으로 이동한 뒤에도 카메라가 계속 돌아서 구도가 흐트러집니다. 끄고 보면 프리셋 5개 모두 구조물 밖에서 대상을 잡습니다. 다만 구조물이 빽빽해서 연못·토리이 구도가 꽉 찹니다.
- **비용이 가장 큽니다.** 73분 44초, 툴 호출 159회, 서브에이전트 토큰 422,038. 가장 먼저 띄웠는데 가장 늦게 끝났습니다. Opus(21분, 16만 토큰)의 약 3.5배 시간, 2.6배 토큰입니다.

### claude-opus-5 · 정답지

감독자가 직접 작성한 기준 구현입니다. 914줄로 가장 짧습니다.

- 장점: 연못 규모(물 복셀 약 380개), 물 투명도 0.6으로 잉어가 수면 아래로 비침, 프리셋 5개 모두 구조물 밖, `performance.now()` 이징.
- 약점: 탑 상륜부가 단순한 기둥에 금색 한 칸뿐이고(DeepSeek·Sol이 낫습니다), 하늘 그라데이션 8스톱으로 새벽·황혼 전환이 거칩니다. 잉어도 5복셀 일자 몸통입니다.
- 작성 중 직접 밟고 고친 것: 첫 화면이 섬을 잘라먹음, 탑이 너무 가늘고 높음, 연못이 탑 기단과 겹침, 다리 난간이 통나무처럼 두꺼움, 연못 프리셋이 나무 속에 박힘, `dt` 누적 이징.
- 정답지라고 해서 모든 면에서 최고는 아닙니다. 구조적 견고함의 기준점으로 보면 됩니다.

## 이 과제가 걸러내는 것

### 1. `vertexColors` 함정 — 정적 검증으로는 절대 안 잡힌다

여덟 개 중 두 개(Astra, Luna)가 걸렸습니다. 둘 다 사양서 검증 커맨드를 통과했고, 콘솔 에러도 없고, 60fps로 돌고, 복셀 수도 정상입니다. **화면을 눈으로 봐야만 보이는 결함**입니다.

```js
// ❌ InstancedMesh + setColorAt()에 이걸 켜면 전부 검게 나온다
new THREE.MeshLambertMaterial({ vertexColors: true })

// ✅ instanceColor는 플래그 없이 자동 적용된다
new THREE.MeshLambertMaterial()

// ✅ vertexColors는 지오메트리에 color 속성이 있을 때만
geometry.setAttribute('color', new THREE.BufferAttribute(colors, 3));
new THREE.PointsMaterial({ vertexColors: true })
```

### 2. 브라우저로 자기 결과물을 봤는가

결과가 가장 크게 갈린 지점입니다.

| 모델 | 브라우저 확인 | 결과 |
|---|---|---|
| claude-opus-5.5 | ✅ 성공 — 보고 고침 | A |
| claude-sonnet-5.5 | ✅ 성공 — 보고 고침 | A |
| gpt-6.1-sol | ❌ 차단 | A (보지 않고도 맞음) |
| gpt-6.1-terra | ❌ 차단 | B (보지 않고도 맞음) |
| gpt-6-astra | ❌ 할당량 초과 | **F — 검은 화면 그대로** |
| gpt-6-luna | ❌ 확인 안 함 | **F — 검은 화면 그대로** |

보지 못하면 결함이 그대로 남을 확률이 높습니다. Sol과 Terra는 보지 못하고도 맞췄지만, Astra와 Luna는 보지 못해서 틀렸습니다.

### 3. 카메라가 구조물 안에 박힌다

프리셋 좌표를 대상 근처로 잡으면 나무 캐노피·토리이·탑 처마 안으로 카메라가 들어갑니다. qwen은 3개, Astra는 1개가 걸렸습니다. Opus와 정답지는 처음에 똑같이 걸렸다가 눈으로 보고 고쳤습니다.

### 4. 첫 화면 프레이밍

섬 반지름 22에 탑 높이 30이 넘으면 화각 45°에서 카메라를 꽤 멀리 빼야 전체가 들어옵니다. Luna와 Terra는 섬이 잘렸고, 정답지도 처음엔 잘렸습니다.

### 5. 프레임 누적 이징

`flight.t += dt`로 카메라 이동을 진행하면, 창이 백그라운드로 가서 프레임이 떨어질 때 1.2초짜리 연출이 십수 초로 늘어납니다. 60fps에서는 문제가 안 보이지만 저사양·백그라운드에서 갈립니다. 벽시계(`performance.now()`) 기준으로 짠 건 Opus와 Sonnet 둘뿐입니다. 둘 다 브라우저로 자기 결과물을 직접 본 모델이라는 점이 우연은 아닐 겁니다.

## 측정상 주의

검증에 쓴 브라우저 패널이 백그라운드로 가면 `requestAnimationFrame`이 초당 1–6틱으로 쓰로틀됩니다. 이 상태에서 프리셋을 누르면 카메라가 안 움직이는 것처럼 보여 **결함으로 오판하기 쉽습니다.** 실제로 검증 중 세 번 그럴 뻔했습니다. 그래서 프리셋 판정은 rAF 레이트를 먼저 재고, 쓰로틀 상태면 30초 이상 기다려 최종 위치를 확인했습니다. qwen의 프리셋 결함만 60fps 상태에서 재현해 판정했습니다.
